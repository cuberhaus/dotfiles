# Automation notifications and the Linux-only jobs

Read before changing `.local/scripts/lib/cuberhaus-progress.sh`, the `--notify` flag of any job in `.local/scripts/automation/`, or the `inbox-collector` and `desktop-shortcut-cleanup` jobs. Agents run the tests named below; they never run `make install-automations`, `sudo`, or a real `inbox-collector` against the user's folders (`--dry-run` is fine).

- **The library**: `lib/cuberhaus-progress.sh` is sourced, never run. `progress_start TASK TITLE [VERB] [UNIT] [DELAY]`, `progress_update`, `progress_finish success|warning|failure [--quiet] [--message TEXT] [LINES…]` and `progress_abort` (for an `EXIT` trap) are the whole API. Every function returns 0 and does nothing before `progress_start`, so a notification problem can never fail a job, and a script calls them only when it was given `--notify`. Each job loads the library from beside itself or from `../lib/`, and falls back to no-op functions (printing one line when `--notify` was asked for) when it is missing. It must stay plain bash 3.2, because the user-level jobs also run on macOS, where it shows nothing.
- **Delivery**: `gdbus call … org.freedesktop.Notifications.Notify` is the primary path, because it returns the id used as `replaces_id` (one notification updated in place, then replaced by the summary), accepts the `value` hint that dunst and KDE draw as a bar, and can `CloseNotification` a bar. `notify-send` is the fallback (`--hint=int:value:N` plus the `x-canonical-private-synchronous` hint, since 0.7.9 has neither `-r` nor `-p`); it cannot close a bar. Strings are escaped twice: markup (`& < >`) for the daemon, then GVariant quoting (backslash and quote) for `gdbus`. Do not build the call by interpolating raw text. Every notification is normal urgency with the server's default timeout; nothing is made persistent.
- **Quiet policy (differs from Windows)**: a bar appears only after `DELAY` seconds (10 for every job that updates one; `desktop-shortcut-cleanup` is too short for a bar and shows only its summary), is throttled to one update per second and skips an update that would repeat the last one. A successful run that did nothing finishes with `--quiet`: nothing is shown and a bar already on screen is closed. Warnings and failures always show. Windows keeps a quiet entry in the notification centre for a no-op run; the Linux daemons have no portable equivalent, so a no-op day is silent. Do not "fix" this by adding a banner.
- **Ids live in a private temp directory** (`mktemp -d`, `id.<uid>` files), not in variables, because `brew upgrade | watch_upgrade` runs the parser in a pipeline subshell and the summary in the parent must still replace its bar. `progress_finish` and `progress_abort` remove the directory.
- **The root job** (`system-maintenance`, run by the system timer) cannot reach a session bus, so the library finds the active graphical sessions with `loginctl list-sessions` and `loginctl show-session` (x11, wayland or mir; not root; one per uid) and runs `gdbus` or `notify-send` as that user through `runuser -u USER -- env DBUS_SESSION_BUS_ADDRESS=unix:path=/run/user/UID/bus XDG_RUNTIME_DIR=/run/user/UID …`. With nobody logged in nothing is shown; the journal still has the run. The root script and its library must stay root-owned: `install` copies `cuberhaus-progress.sh` next to `/usr/local/libexec/cuberhaus-system-maintenance`, and the script looks for it only beside itself (its own directory, then a `lib` folder next to it), never in a user home, because a library a user can write and a root job sources is a privilege escalation. `uninstall` removes both files.
- **Progress sources**: `workspace-pull` steps once per repository and says "N updated, M already up to date" (an update is a changed `HEAD`, not a successful pull). `user-package-maintenance` counts `brew outdated --quiet` and `yay -Qua` first and parses `==> Upgrading NAME` and `==> Making package: NAME`; the Homebrew header `==> Upgrading 2 outdated packages:` has spaces and must not count. `system-maintenance` on apt runs `apt-get -o APT::Status-Fd=3` into a FIFO read by a watcher (`dlstatus:` lines move the bar over the first 40 %, `pmstatus:` lines over the rest; with no download the install uses the whole bar), and the script `wait`s for the watcher before the summary so a late bar cannot replace it. On pacman it reads `-Syu --noprogressbar` through `tr '\r' '\n'` and matches `(n/m) upgrading|installing|reinstalling|downgrading|removing`. `dlstatus:` was checked against a real apt; the `pmstatus:` format is handled from apt's documented model and was only exercised with stubs, so re-check it on a machine where root can run `apt-get full-upgrade`.
- **`inbox-collector`**: moves the stable items of each source folder into a folder named after the source inside the Desktop inbox (`0 Inbox`; an existing `0 - Inbox` is used when no name is given). The sources are `~/.config/cuberhaus-automations/inbox-collector-sources.txt` (tracked in this repo, so `--add-source` edits the checkout through the Stow link; entries are paths, `~`, `$HOME`, or `xdg:NAME[/sub]` such as `xdg:DOWNLOAD` and `xdg:PICTURES/Screenshots`). It never overwrites (a taken name gets a space and `(2)` before the extension), skips hidden items, symbolic links, `*.crdownload`, `*.download`, `*.part`, `*.partial`, `*.tmp`, `~$*` files and anything changed in the last `--minimum-age-minutes` (default 10, 0 to 1440), leaves a subfolder alone when it holds one of those, never moves the inbox or a PARA folder (`0 Inbox`, `0 - Inbox`, `1 Projects`, `2 Areas`, `3 Resources`, `4 Archive`, `Shortcuts`), and journals every move (`inbox-collector-last-run.journal`, NUL-separated pairs) so `--undo` can reverse the last run, skipping an item whose original place is taken or whose copy is gone and keeping those records. `--dry-run` moves nothing.
- **`desktop-shortcut-cleanup`**: moves loose `*.desktop` and `*.url` files (and links to them) at depth 1 of the Desktop (`xdg_user_dir DESKTOP`, `~/Desktop` by default; hidden names stay) into `Desktop/Shortcuts`, replacing a same-name file there, and creates the folder only when something moves. `--dry-run` previews. Because launchers move, anything that looks for a launcher on the Desktop must also look in `Shortcuts`: `audit_installation.py` (`app_files`, `DESKTOP_SHORTCUTS_FOLDER`) and `davinci_resolve_install.sh` (`system_files`) do, each with a test; keep that when adding another consumer.
- **`lib/xdg-dirs.sh`**: `xdg_user_dir NAME [FALLBACK]` reads `user-dirs.dirs` the way GLib does (a leading `$HOME/` is expanded, nothing else; a relative path or the home folder itself means "no such folder" and gives the fallback) so the jobs work without `xdg-user-dir`, which a systemd user service or a minimal install may lack.
- **Scheduling**: the user units are `cuberhaus-workspace-pull`, `cuberhaus-user-package-maintenance`, `cuberhaus-inbox-collector` (daily 20:00) and `cuberhaus-desktop-shortcut-cleanup` (daily 10:45), each `Type=oneshot` with `ExecStart=/bin/bash %h/.local/scripts/automation/<job> --notify` and a `Persistent=true` timer; the root unit is `cuberhaus-system-maintenance`. `make audit-installation` checks the four user timers (`LINUX_USER_TIMERS`) and `tests/test_installation_audit.py` also checks that every audited timer ships with a service whose `ExecStart` ends in `--notify`. macOS installs only the two older jobs, without `--notify`; WSL installs none (Windows Task Scheduler runs the WinDotfiles counterparts).
- **Tests**: `tests/test_progress_lib.sh` (library: delay, ids, quiet, escaping, throttle, backends), `tests/test_automation_notifications.sh` (`--notify` in `workspace-pull`, `user-package-maintenance` and `system-maintenance` against real temporary git repositories and stub `brew`, `yay`, `apt-get`, `pacman`, `gdbus`, `loginctl`, `runuser`, with a fake clock; `AUTOMATION_DIR` points it at a mutated copy), `tests/test_inbox_collector.sh` and `tests/test_desktop_shortcut_cleanup.sh` (`SCRIPT=` points at a mutated copy), and `tests/test_automation_install.sh` (the Linux paths of `install`, `uninstall` and `observe` against stub `systemctl`, `sudo` and `journalctl` in a throwaway `HOME`; `REPO_ROOT=` points it at a mutated copy). They run without a desktop and never touch the real notification daemon, `/usr/local`, or `sudo`: root is faked through an `id` stub. A new behaviour needs a test that fails without it.
- **Windows counterpart**: `WinDotfiles` shows the same progress and summaries through a status-file contract and a watcher that registers its own toast AppId. The Linux jobs notify directly instead (no second process), and differ on the quiet policy above. Change the shared wording ("<Task> finished", "finished with problems", "failed", "Took X.") in both repositories together.
