# Shell tools and interactive-shell behaviour

Read before changing `update`/`updateall`, `cleanup`, `git-recurse`, `.local/Mini/.bashrc`, the antigen bundles in `.config/zsh/.zshrc`, the `ARGV0` guard in the `.zshenv` files, or the Bash prompt in `.bashrc`.

- **`update` and `updateall` steps**: both are functions over `_update_run`, not aliases. An alias appends typed arguments to its last command, so it cannot offer `--dry-run`/`--help`, and zsh-syntax-highlighting paints it red whenever any command inside it is not installed, however well guarded. They are functions rather than scripts because `updateall` runs `antigen update` and `antigen` is a function of the interactive zsh session. Run each new step through `_update_step`: it honors `--dry-run`, tallies failures, and never stops the steps after it (`--best-effort` keeps a step out of the summary when it fails only for having nothing to do, like `xcode-select --install`). Run every step in the foreground: `nvim +PlugUpdate` draws a full-screen UI, so the shell stops it as a background job (`suspended (tty output)`) before it updates anything. The Emacs package update is the one background job, because its window stays open. Never call `pip install --user` unconditionally: Debian/Ubuntu, Arch and Homebrew mark Python `EXTERNALLY-MANAGED` (PEP 668) and apt owns `python3-pynvim`, so `pip_user_upgrade` skips those interpreters (and virtualenvs); do not force it with `--break-system-packages`. On Arch and Manjaro run yay as `command yay -Syu` and detect the binary with the wrapper unset: `command -v yay` finds the `yay()` wrapper (`yay -S --noconfirm --needed`) even when yay is not installed. `tests/test_updateall.sh` covers it.
- **`cleanup` steps**: `cleanup` is the script `.local/scripts/bin/cleanup`, not an alias or a function. An alias appends typed arguments to its last command, so it cannot offer `--dry-run`/`--help`; a function in `.config/zsh/aliases` needed `command` in front of every tool (this file aliases `df` to `df -h`, and the Arch/Manjaro `yay()` wrapper would run instead of `yay -Sc`); a script has neither problem and also runs from bash. Never define a `cleanup` function or alias here: it would shadow the script. Zsh puts `~/.local/scripts/bin` on `PATH` (`.zshenv`); plain bash does not, like `git-recurse`. Run new steps through `step`, which honors `--dry-run` (only read-only probes such as `docker info`, `snap list` and `docker volume ls` still run), tallies failures, and returns the command's failure. Prune Docker containers, then ask about volumes, then prune images and build cache (an image used by a stopped container survives the image prune, a volume used only by a stopped container is unused once it is gone, and the slow unattended prunes belong after the questions); probe the daemon once with `docker info`.
- **`cleanup` and Docker volumes**: volumes hold data that nothing rebuilds, so they are never pruned in bulk. Only a per-volume answer deletes: list `docker volume ls --filter dangling=true`, show size, age, origin and driver, default to No, and remove by name with `docker volume rm NAME`. Never `docker volume prune` and never `-f` (without it Docker refuses a volume that any container, even a stopped one, still references). Nothing is deleted under `--dry-run` or when stdin or stdout is not a terminal; Enter, `n`, `q`, an unreadable answer and end of input all keep the volume. The `l` answer lists a local volume from a throwaway container with a read-only, offline mount and `--pull never`, reusing a local image that has `ls`. The Docker CLI rewrites a literal `\t` or `\n` in `--format` before parsing it, so keep both outside `{{ }}`. `tests/test_cleanup.sh` covers all of it with stub commands, and a Python `pty` helper types the answers because the prompts only appear on a terminal.
- **`git-recurse` summaries**: after its `Done:` line the script prints a summary chosen from the command. `git pull` lists the repositories it updated (HEAD is recorded around the command); `git status` lists the repositories that are not clean, as `2 modified, 1 untracked, ahead 1` (conflicted, staged, modified, untracked, ahead, behind, in that order; a path both staged and modified counts under each). `-S` forces one and `GIT_RECURSE_SUMMARY=0` turns both off. The status summary never reads the text the command printed, which is localized and may be `--short`: each job runs its own `git status --porcelain --branch` (`GIT_OPTIONAL_LOCKS=0`, same timeout) and `describe_status` parses that. It is plain shell because every repository runs at once and a program started per repository (an awk was measured) lengthens the whole run. `describe_status` answers 1 for "clean", so a probe or parse that fails fails the repository instead of passing as clean. The script colours with `tput` even when its output is captured, so `tests/test_git_recurse.sh` pins `TERM=dumb`; without that the test fails in any real terminal. The test loads the parser and the probe from the script to cover porcelain cases and the path without a `timeout` command (macOS), and runs the whole script on real repositories in each state. Mini carries a second copy of the script that runs the same tests (see the Mini `.bashrc` bullet), so a new behaviour belongs in the part of `tests/test_git_recurse.sh` that goes through the command alone.
- **Mini `.bashrc`** (`.local/Mini/.bashrc`): the portable file, copied by hand to `~/.bashrc` on a machine that has none of these dotfiles (like `.local/Mini/.gitconfig`), so it cannot source anything from the repository and carries condensed copies of the commands that matter there. A request to add an alias or command "everywhere" includes it. `clone-all`, `clone-team`, `git-recurse` and `git-ahead` are such copies: functions with a subshell body (`name() ( … )`, so `exit`, variables, inner functions, options, traps and descriptors never reach the interactive shell). The clone commands sit over two helpers, `_clone_repo_dir` and `_clone_configure_repo`, that copy `resolve_repo_dir` and `configure_tracked_repo_git` from `.local/scripts/lib/git-repo-defaults.sh`. Change an original and its Mini copy in the same run; `tests/test_mini_bashrc.sh` runs both side by side (the real `clone-all`, `clone-team` and `git-ahead` scripts and the library's identity, hooks and path rules, compared on output, errors, exit status, settings and hooks run) and fails when they drift. `git-recurse` is held to its whole suite instead: `tests/test_git_recurse.sh` takes the command from `GIT_RECURSE_UNDER_TEST`, and every test that goes through the command alone (all but the white-box tests of the script's own functions, after the early exit) must pass for the script and the copy alike, so add a behaviour test there, not in the Mini test. The patterns copied from the script (the transient-error list, the pull and status regexes) are compared word for word, so a change to one file fails until the other follows. The copy has every option and variable of the script except `-k` (it adds one Mac's ssh key), runs with or without `tput` and `timeout`/`gtimeout`, and avoids Bash features newer than 3.2 (macOS ships it as `/bin/bash`; no test runs on a real 3.2, so keep `mapfile`, `wait -n` and `${var^^}` out by hand). Put new code above the aliases section, because bash bakes an alias that is already defined into the body of a function parsed after it: the aliases `grep -i`, `mv -iv` and `rm -vI` are why these functions call `command grep`, `command mv` and `command rm`, and a test loads the file three times to catch a miss. `set keyseq-timeout 50` near the top overwrites the positional parameters of whoever sources the file, so a test passes data through the environment. `gr`, `gah` and `status` call these functions, so they work on a machine without the dotfiles. `gclean` is a condensed copy of `git-clean-branches` (no `--depth` or `--no-fetch`), and `git-ci-status`, a 479-line Python tool, has no Mini copy. `.local/scripts/lint_helpers.sh` lints it (`LINT_PATTERNS`).
- **Distro-specific antigen bundles**: the oh-my-zsh `archlinux` bundle loads only when `DISTRO` is `arch` or `manjaro` (guard in `.config/zsh/.zshrc`). Unguarded, it adds pacman/AUR aliases and helpers like `upgrade` and `paclist` that cannot work without `pacman`, and zsh-syntax-highlighting paints them red. Guard on `DISTRO`, not `command -v pacman`: Debian and Ubuntu ship a `pacman` arcade game in `/usr/games`. While `~/.config/antigen/init.zsh` exists, antigen ignores every `antigen bundle` call and replays that cache; it rebuilds only when `.zshrc` is newer than its `.zwc`, so a faked `DISTRO` in a real shell can poison the cache. Test guards with a stub antigen. `tests/test_zshrc_bundles.sh` covers it.
- **AppImage terminals and `ARGV0`**: zsh uses an exported `ARGV0` as `argv[0]` of every command it runs, and Cursor, an AppImage, hands it to its shells, so Python started there reported the AppImage as `sys.executable` and anything that re-launched it (`subprocess.run([sys.executable, …])`, `multiprocessing` workers, the interpreter YouCompleteMe records) started the editor. `.zshenv` and `.config/zsh/.zshenv` carry an identical guard block that drops `ARGV0` when `$APPIMAGE` is set. Both files are needed: zsh reads `$ZDOTDIR/.zshenv` and skips `~/.zshenv` when `ZDOTDIR` is already set in its environment, as in Cursor's shells, and the guard must stay the first thing each file runs. `~/.config/zsh` is a folded symlink into this checkout, so the new file applies at once, but shells that were already running keep the old value until Cursor restarts. Tests of Python tooling still resolve the interpreter themselves instead of trusting `sys.executable`, and the `ycm.sh` check on the recorded interpreter stays as a second line of defence. `tests/test_zsh_argv0.sh` runs the real blocks in zsh, against a control that shows the quirk.
- **Bash prompt**: the colored prompt in `.bashrc` assigns `PS1` once and only refreshes the variables it references from `PROMPT_COMMAND`, because VS Code/Cursor shell integration wraps `PS1` and re-wraps it whenever it changes. Do not re-add prompt plugins that rebuild `PS1` on every prompt (the removed `bash-git-prompt` did). It honors `NO_COLOR`, skips `TERM=dumb`, and `PROMPT_GIT=0` hides the git segment. Chat-tool terminals run `bash --noprofile --norc` on purpose and stay plain. `tests/test_bashrc_prompt.sh` covers it.
