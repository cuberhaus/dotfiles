# Installation audit: undeclared packages and apps

Read before changing `.local/scripts/audit_installation.py` (`audit_extra_packages`, `audit_self_installed_apps`), `DEB_FILE_PACKAGES`, `STANDALONE_INSTALLERS`, or the handling of `~/.config/dotfiles/known-extra-packages`. Removal commands the audit prints stay interactive (never `-y`, `--noconfirm`, or `--purge`).

- **Packages installed outside the bootstrap**: `audit_extra_packages` in `audit_installation.py` is the reverse of the package check. It reports what each manager says was installed on request (`apt-mark showmanual`, `snap list`, `pacman -Qqe`, `brew leaves` and casks) but no active bootstrap function declares, only for managers the profile declares packages for, as `[NOTICE]` findings that never change the exit code (`--list-extra` prints them as `manager:name`). A notice carries a `Fix:` command only when it is safe to paste. A `.deb` installed through a variable and a standalone installer's package array are invisible to `expected_packages`, so `DEB_FILE_PACKAGES` maps each `local <name>_deb=` variable of the bootstrap to its package (a new one needs an entry; `tests/test_audit_extra_packages.py` fails without it) and `STANDALONE_INSTALLERS` names the script array of each installer a profile calls (asusctl, and the NVIDIA Container Toolkit's array in `base_functions`). apt marks hundreds of OS packages as manual, so a removal command may name only an apt package that a `Requested-By` transaction in the retained apt logs installed on request (not `automatic`), a snap that Canonical does not publish, and nothing that matches `SYSTEM_PACKAGE_PATTERNS` (kernel, boot loader, firmware, drivers); the rest get a notice of their own with no command, because a pasted `apt-get remove language-pack-en` is not a suggestion to make. The commands stay interactive (`sudo apt-get remove`, `sudo snap remove`, `sudo pacman -Rs`, `brew uninstall`): never add `-y`, `--noconfirm` or `--purge`, and never use `yay`, whose zsh wrapper turns every call into an install. A package is kept by declaring it in the bootstrap or by listing `manager:name` in `~/.config/dotfiles/known-extra-packages` (per machine, outside the repository). The report wraps to the terminal (`output_width`, 60 to 100 columns) with a hanging indent and breaks the command with `\` so it still pastes as one command; `Reporter.result` accepts a multi-line message for this, so never print a package list as one unwrapped line. Only the apt and snap paths have run on a real machine; pacman and Homebrew are covered with stubs. `tests/test_audit_extra_packages.py` covers it.
- **Apps installed outside the bootstrap**: `audit_self_installed_apps` in `audit_installation.py` covers what the package check cannot see. An app that came with its own installer (an AppImage, Zed's `install.sh`, GPT4All's installer) is in no package manager's database, but it leaves a launcher in `$XDG_DATA_HOME/applications` (`~/.local/share/applications`), so that is what the audit reads. One `[NOTICE]`, which never changes the exit code, lists each application launcher (`Type=Application`, not `Hidden=true`) whose program exists and lies inside `$HOME` once symbolic links are followed, so `~/.local/bin/code` pointing at a system package and a launcher left behind for a deleted program do not count. Only the `[Desktop Entry]` group is read, because a `[Desktop Action …]` group has an `Exec` and a `Name` of its own. An `env VAR=value` prefix is skipped, a bare command name is looked up on `PATH`, and a program that cannot be told (`sh -c '…'`, a relative path, unbalanced quotes) is skipped. A launcher is declared when an uncommented line of the profile's entrypoint, or of a function it reaches (`active_bootstrap_code`, the same reading as the package check), names its file with word boundaries (`names_file`), as `ai_tools_install` does for `cursor.desktop` and `antigravity.desktop` on `arch`; a commented-out block and an uncalled function declare nothing. An installer that writes its own launcher (Zed's) is not recognized that way, so accept such an app by listing `app:KEY` (the launcher's file name without `.desktop`; the bare key works too) in `~/.config/dotfiles/known-extra-packages`. `--list-extra` prints the apps as `app:KEY` after the packages, so appending its output accepts everything at once. The audit deletes nothing. Under an app it prints a `Fix:` command only where the place of the program proves what belongs to the app (`app_location`), and nothing under any other app, whose owner uses its own uninstaller or deletes it by hand. The proof is one of: an AppImage (`.appimage` in any case, a file) is the file alone; a folder directly in `~/.local/opt`, `~/.opt`, `~/opt` or `~/Applications` is the app; so is a `*.app` bundle directly in `~/.local` (Zed's `install.sh`; a plain `~/.local/<x>` is shared with pipx and cargo and proves nothing); so is the nearest folder below `$HOME` that holds a Qt Installer Framework `maintenancetool` or `MaintenanceTool` (GPT4All, the Qt SDK). The home folder, a folder that holds apps, `~/.local/bin`, `~/bin` and any folder named like a part of a prefix (`bin`, `lib`, `share`, …) are never the result, so a script in `~/.local/bin` or a program in a folder of the owner's own gets no command. `app_files` adds the symbolic links in `~/.local/bin` and `~/bin` that lead into the app and every `.desktop` file that starts a program inside it, in the launcher folder, on the desktop (`user_desktop_dir`: `XDG_DESKTOP_DIR` of `user-dirs.dirs`, `~/Desktop` by default; the Qt installer leaves a shortcut there) and in its `Shortcuts` folder (`DESKTOP_SHORTCUTS_FOLDER`), where the `desktop-shortcut-cleanup` automation moves loose launchers. The command is `rm -rI -- PATH…` (`removal_words`): `-I` asks once before a recursive removal and still asks when the answer comes from a pipe, it never has `-f` or `sudo`, and it names the app, its links and its launchers but never its settings or data (`~/.config/zed`, `~/.local/share/nomic.ai`), which the owner decides on. A path inside `$HOME` is written `~/…` when `SHELL_SAFE_PATH` needs no quoting; any other is quoted whole and written in full, because a tilde inside quotes is not expanded (`shell_path`, which also covers a `$HOME` that is a symbolic link, as `/home -> /var/home`). A wrong folder in `app_location` is a deleted folder, so never widen it to a guess: a new layout needs a test of the layout that gets a command and of the lookalike that gets none. A tool without a launcher stays invisible. Name every new `audit_*` function that `main()` calls in `MainTests.AUDITS` (`tests/test_audit_extra_packages.py`), or its tests run that audit against the machine's own files. `tests/test_audit_self_installed_apps.py` covers it with a fake home, a fake repository and real files, and runs the printed command with `bash` (answering `y`, `n`, an empty line and end of input) to check that the neighbours of the app survive.
